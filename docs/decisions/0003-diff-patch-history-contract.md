# Diff·Patch·편집 루트·이력 연결 계약

- 상태: 부분 승인·설계안. 항목별 승인 상태와 적용 단계는 아래 표가 기준이다.
- 근거: 사용자는 빈 화면·여러 최상위 노드를 고정 데이터 루트 아래 관리하는 방식을 선택했다.
- 적용: P1-02·P1-03·P1-04. 이 문서 작성으로 해당 기능이 구현된 것은 아니다.
- 관계: [결정 0001](0001-vnode-initialization.md)의 P1-00 초기화는 유지한다. 아래 편집 루트 전환의 세부 연결은 P1-02 착수 시 확정한다.

이번 문서 수정의 승인은 위 설계안 전체의 승인이나 구현 착수를 뜻하지 않는다. 설계 선택, 구현, 실행 검증, 사용자 수용을 구분한다. 특정 항목을 확정할 때는 선택한 동작과 근거를 해당 행에 반영하며 관련 없는 대기 항목의 상태는 유지한다.

P1-02 착수에는 해당 단계의 루트 연결·경로·비교·Patch·오류 처리 계약만 필요하다. 이력 계약의 확정·구현은 P1-04에 둔다. P1-03의 복합 변경 검사가 기본 추가·삭제·교체·텍스트·속성·동일 트리 검사를 대신하지 않는다.

## 편집 데이터와 DOM의 경계

고정 데이터 루트의 사용은 승인됐으며, 아래 객체 표현·패널 연결·전환 절차는 P1-02에서 확정할 세부 설계안이다.

Phase 1의 상태는 `{ kind: 'element', tag: 'div', props: {}, children }` 형태의 고정 데이터 루트다. `children`은 패널 안의 모든 `childNodes`를 변환한 결과이며 주석만 제외한다. 공백을 포함한 텍스트·빈 자식 목록·여러 최상위 요소를 허용한다. SVG 등 기존 지원 범위 밖 입력은 명시적으로 오류 처리한다.

패널의 id·class·contenteditable은 데이터에 넣지 않는다. 고정 루트는 `actual-area` 또는 `test-area`의 자식들을 묶는 데이터 표현이며, 렌더한 div를 다시 패널 안에 중첩하지 않는다. 초기화·이력 복원 시 `renderVNode(snapshot)`으로 임시 DOM을 만든 뒤 그 자식만 패널에 옮긴다. Patch에는 실제 패널 노드를 고정 루트의 DOM 앵커로 전달한다. 따라서 반복 Patch 때 감싸는 div가 늘어나지 않는다.

이 설계안을 채택하면 P1-02 전환 시 두 패널과 초기 상태를 이 표현으로 함께 맞춘다. `firstElementChild`만 읽어 다른 최상위 노드를 누락하지 않는다. 고정 루트 자체의 props·tag는 편집 대상이 아니다.

## Diff의 입력과 변경 목록

`diff(previousVNode, nextVNode)`는 DOM을 읽거나 변경하지 않고 새 변경 배열을 반환한다. 입력 VNode도 변경하지 않는다. 두 입력 루트는 요소 또는 텍스트이며 null 루트는 이번 범위 밖이다. Phase 1의 빈 화면은 고정 루트의 `children: []`로 표현한다.

`path`는 **이전 VNode 트리의 `children` 기준** 인덱스 배열이다. `[]`는 루트, `[1, 0]`은 루트의 두 번째 자식 아래 첫 자식이다. VNode에서 제외한 주석은 세지 않으며, 공백·줄바꿈 텍스트는 센다. 실제 DOM의 `childNodes[index]`에 그대로 대입하지 않는다.

### 실제 DOM에서 같은 경로를 찾는 규칙

각 경로 단계에서 아래 순서로 실제 자식 노드를 찾는다. 변환기가 VNode 자식을 모으는 순서와 동일해야 한다.

1. 현재 노드가 HTML `template` 요소이면 자식을 담는 컨테이너는 `node.content`, 그 외에는 현재 노드 자신이다.
2. 컨테이너의 `childNodes`에서 주석(`nodeType === 8`)만 제외한 목록을 만든다. 요소·텍스트의 순서와 공백은 유지하고, 지원하지 않는 노드를 조용히 제외하지 않는다.
3. 이 목록의 인덱스로 다음 실제 노드를 선택한다. 선택한 노드 아래로 내려갈 때도 같은 처리를 반복한다. 텍스트 아래로 내려가거나 경로가 범위를 벗어나면 적용 전에 오류 처리한다.

경로의 각 값은 0 이상의 정수여야 한다. Phase 1에서 `[]`는 고정 데이터 루트에 대응하는 실제 패널 노드다. 패널의 id·class 등 UI 속성은 콘텐츠 비교 대상이 아니다.

경로를 맞추기 위해 원본 DOM의 주석을 삭제하거나, 공백을 지우거나, 인접한 텍스트 노드를 합치지 않는다. 주석 자체는 변경·이력의 대상이 아니므로 주석의 추가·삭제만으로는 변경을 생성하지 않는다. 주석을 포함한 부모 서브트리를 제거·교체하거나 스냅샷으로 재구성할 때 주석 보존은 보장하지 않는다.

`INSERT`의 `parentPath`도 같은 규칙을 사용한다. `index`는 이전 부모 VNode의 자식 목록 기준이며 `0`부터 이전 자식 수까지 허용한다. 이전 자식 수보다 작으면 위 규칙으로 찾은 실제 자식 앞에 삽입하고, 같으면 실제 컨테이너 끝에 추가한다. 빈 부모의 삽입 위치는 `0`이다. `template` 안의 삽입·삭제는 `template.content`에서 수행한다.

모든 경로와 삽입 기준은 DOM을 변경하기 전에 해석해 실제 노드 참조로 보관한다. 삽입·삭제 후 바뀐 자식 목록으로 이전 경로를 다시 해석하지 않는다.

### 사용자 검증용 경로 예제

아래는 해당 HTML의 루트 요소를 `[]`로 두고 읽는 **설계 검토 예제**다. 실제 Patch 실행 결과가 아니며, 경로 해석과 Patch의 자동 검사는 P1-02·P1-03 구현 때 추가한다.

| 입력 또는 조건 | 확인할 경로 | 기대 대상·동작 |
| --- | --- | --- |
| `<p>A<!-- 메모 -->B</p>` | `[0]`, `[1]` | 각각 텍스트 `A`, `B`. 주석은 세지 않음 |
| `<p>A<!-- 메모 -->B</p>` | `[2]` | 주석 제외 후 자식은 두 개이므로 범위 오류 |
| `<p> <b>B</b> </p>` | `[0]`, `[1]`, `[2]` | 공백 텍스트, `b` 요소, 공백 텍스트 |
| `<div>A<!-- 메모 --><template><b>B</b><!-- 설명 -->C</template>D</div>` | `[1]`, `[1, 0]`, `[1, 0, 0]`, `[1, 1]`, `[2]` | `template`, 그 content의 `b`, `b`의 텍스트 `B`, content의 텍스트 `C`, 바깥 텍스트 `D` |
| `<p>A<!-- 메모 -->B</p>`에 텍스트 `X` 삽입 | `parentPath: []`, `index: 1` | 실제 `B` 앞에 삽입. 주석을 제외한 결과는 `A`, `X`, `B` |
| `<p>A<!-- 끝 --></p>`에 텍스트 `X` 삽입 | `parentPath: []`, `index: 1` | 실제 컨테이너 끝에 추가하여 `A<!-- 끝 -->X` |
| `<template><!-- 메모 --></template>`에 `b` 요소 삽입 | `parentPath: []`, `index: 0` | `template.content` 끝에 추가. 주석만 있는 부모도 VNode 자식 수는 0 |

사용자는 주석 제외·공백 보존·template 내부 탐색·삽입 위치가 의도에 맞는지 확인한다. 이후 런타임 검사는 경로가 선택한 실제 노드의 참조와 변경 후 VNode를 확인한다. 경로 해석만으로 DOM을 변경하지 않는지와 잘못된 경로를 적용 전에 거부하는지도 검사한다. 설계 검토 통과와 런타임 검사 통과는 구분한다.

### 변경 목록

| 변경 | 필드 | 의미 |
| --- | --- | --- |
| `INSERT` | `parentPath`, `index`, `vnode` | 이전 부모 VNode 자식 목록의 index 위치 앞에 새 서브트리 삽입. 이전 길이이면 실제 컨테이너 끝에 추가 |
| `REMOVE` | `path` | 대상 서브트리 삭제 |
| `REPLACE` | `path`, `vnode` | 대상 서브트리 교체 |
| `TEXT` | `path`, `text` | 텍스트 노드 내용 변경 |
| `PROPS` | `path`, `set`, `remove` | 변경된 속성의 이름·값과 제거할 속성 이름 목록 |

기본 비교는 위치 기준이며 key 기반 이동·전역 최소 편집 횟수는 보장하지 않는다. 같은 위치에서 종류·태그가 같으면 속성·텍스트·자식을 비교하고, 다르면 REPLACE 한 건으로 처리하며 그 아래 변경을 중복 생성하지 않는다. 삭제할 서브트리 아래에도 별도 변경을 생성하지 않는다. 같은 트리는 빈 배열이다.

첫 구현은 공통 길이의 자식을 위치별로 비교한 뒤 남은 꼬리를 삭제·추가한다. 중간 삽입은 위치별 변경과 끝 추가로 표현될 수 있다. 변경되지 않은 같은 위치의 노드 참조를 보존한다. 인덱스가 바뀐 노드의 정체성 보존은 별도의 key 지원 과제로 관리한다.

## Patch의 적용과 반환

`patch(root, changes)`는 적용 전 모든 경로의 대상·부모·삽입 기준 노드를 실제 DOM 참조로 확보하고 변경 데이터의 지원 범위를 검증한다. 새 서브트리도 먼저 생성한다. 구조가 어긋나거나 경로가 잘못되면 기존 DOM을 변경하기 전에 오류 처리한다.

변경을 적용하면서 이동한 인덱스로 경로를 다시 탐색하지 않는다. 같은 부모의 삭제는 뒤쪽부터 처리하고, 삽입은 확보한 기준 노드 앞에 변경 목록 순서대로 처리한다. 최초 계약에서 Diff가 생성하지 않는 중복·겹침 변경 목록은 거부한다. 루트 삭제는 허용하지 않고 루트 교체는 새 루트 참조를 반환한다. 변경이 없거나 루트가 유지되면 기존 root를 반환한다. Phase 1의 고정 패널 루트는 교체하지 않는다.

속성·텍스트·자식의 변경 부분에만 DOM API를 적용한다. 정상 Patch를 전체 `innerHTML`·전체 루트 교체로 우회하지 않는다. Phase 2 이벤트·프로퍼티 반영은 별도 계약으로 이 경로를 확장한다.

## 화면과 논리 상태의 갱신 순서

화면 조정은 `demos/phase1/main.js`, 순수 이력 데이터 조작은 `history.js`, DOM 반영은 공통 엔진의 책임이다.

아래 순서는 설계안이다. P1-02에서는 기준 VNode와 화면의 일관성을 먼저 확정하고, 이력 후보 준비·저장·위치 확정은 P1-04에서 추가한다. 적용 중 예외의 복구 수준은 P1-02 구현 전에 사례와 비용을 비교해 결정하며 아래 복구 방식을 이미 승인된 필수 구현으로 해석하지 않는다.

1. 편집 DOM을 읽고 다음 VNode, Diff와 테스트 영역에 반영할 DOM을 준비한다. P1-04에서는 다음 이력 후보도 준비한다. 아직 현재 상태·이력 위치를 바꾸지 않는다.
2. 실제 영역에 Patch하고 테스트 영역을 같은 스냅샷으로 정규화한다. 두 화면 반영이 끝난 뒤 현재 VNode·버튼 상태를 확정하며 P1-04에서는 이력도 확정한다.
3. 준비 중 실패하면 화면을 변경하지 않고 오류를 표시한다. 적용 도중 예상하지 못한 실패가 나면 논리 상태·이력은 유지하고 마지막 확정 스냅샷으로 두 영역을 재구성한다. 이때 미확정 편집은 취소됐음을 표시한다.
4. 복구 렌더링까지 실패하면 편집·Patch·이력 버튼을 잠그고 오류를 표시한다. 오류를 성공·이력 저장으로 기록하지 않는다.

DOM 작업 자체의 원자성을 보장한다고 주장하지 않는다. 실패 복구 시에는 정상 갱신의 노드 참조 보존을 보장하지 않는다. 지원하지 않는 입력·잘못된 경로·적용 중 오류를 각각 재현하여 상태와 화면의 일관성을 검증한다.

## 이력 계약과 의존 관계

이력은 초기 스냅샷 하나와 현재 위치로 시작한다. 외부에서 저장된 VNode를 수정하지 못하도록 스냅샷을 복사해 보관한다. 변경 없는 Patch는 이력을 추가하지 않는다. 과거 위치에서 변경된 Patch가 성공하면 앞으로가기 이력을 잘라 새 스냅샷을 추가한다. 실패한 Patch는 이력과 위치를 바꾸지 않는다.

뒤로·앞으로 이동은 대상 스냅샷을 두 영역에 반영한 후 위치를 확정하며 새 이력을 만들지 않는다. 양 끝에서는 해당 버튼을 비활성화한다. 미확정 편집이 있을 때 이동하면 저장된 상태로 교체한다.

P1-02는 이력에 의존하지 않는 Diff·Patch와 화면 갱신을 완료한다. 이력 저장·이동·분기는 P1-04에서 연결하며, 그때 과제의 전체 Patch 흐름을 통합 수용한다. Phase 2 Hook 상태를 Phase 1 이력에 저장하지 않는다.
