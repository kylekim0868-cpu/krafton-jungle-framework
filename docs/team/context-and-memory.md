# 컨텍스트와 메모리 관리

> **팀 검토 전 초안.** [팀 개발 규칙 목차](../../TEAM_DEVELOPMENT_RULES.md)

## 컨텍스트와 메모리 관리

- **시작할 때** 현재 이슈, 적용할 요구사항, 관련 코드, 확정된 설계, 최근 검증 결과와 미해결 문제 중 이번 작업에 필요한 내용만 읽는다. 과거 결과는 해당 커밋의 기록으로 취급하고, 현재 변경 기준으로 필요한 테스트를 다시 실행한다.
- **종료할 때** Jira 이슈키, 브랜치·커밋·PR, 구현 변경, 실행 명령과 결과, 설계 결정과 이유, 미해결 사항과 다음 작업을 기록한다. 확정된 결정, 제안, 확인된 결과, 미검증 사항을 구분한다.
- **기록할 곳**은 내용의 성격에 맞게 정한다. Compass는 과제 요구사항의 출처, Jira는 작업 범위·담당·상태, PR은 변경·리뷰·검증, 저장소 문서는 공통 실행법과 팀이 확정한 설계의 기준으로 사용한다. 같은 정보를 여러 곳에 복사하기보다 링크로 연결한다.
- 팀이 확정한 뒤 저장소에 이 문서를 두고 `AGENTS.md`에서 참조할 수 있다. 설계 변경을 승인하면 결정 이유와 영향을 기록하고 관련 지침과 검증 기준을 함께 갱신한다.
